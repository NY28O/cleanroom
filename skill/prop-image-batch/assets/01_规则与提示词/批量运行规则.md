# 批量运行规则

启动或续跑前，用户必须明确指定直接存放原图 PNG 的目录路径；未提供时先询问。路径可在仓库外，目录名不限。用 Skill 的 `scripts/batch.py --workspace "工作区" preflight --start N --end M --source-dir "原图库路径"` 只读预检。只有退出码为 0 才能创建批次、续跑或提交图片；失败时提示用户修正并停止，不自动选用默认目录或搜索替代目录。

启动或续跑时，用户必须明确要求修改第几组到第几组（含两端；单组可说“只修改第 N 组”）。未给出完整、明确的范围时，先询问，不提交生成请求。例如：“开始修改第 21 组到第 24 组”。只处理指定区间内清单实际列出的组，不为凑张数向外扩展。

在 `03_批量运行/<批次名>/` 建独立目录，记录起止组号和预检通过的原图库路径，使用[全量核对清单](../03_批量运行/已修改核对清单.md)、[正式提示词](温暖家居_编辑提示词.txt)和[验收规则](图片编辑与验收规则.md)。

1. **选图。** 从只读原图目录顶层选取文件名符合 `数字-数字.png` 的透明道具。排除完整场景、损坏或无法确认的图片。按组号、组内编号升序推进，在整组边界结束；明确指定抽样时仅处理抽中的文件。检查所有选定变体，已有本风格合格输出的跳过。与现有成品同名时，新稿在批次内单独复核，保留已入库文件，不直接覆盖。
2. **定清单。** 按本次范围划分检查节点，保持各组完整。登记文件名、组别、源图校验值和宽高、检查节点与预期输出路径。每组先做一张代表图，在原始大小下确认绘本画法和摆放，再处理同组其余变体，不交叉提交不同组。
3. **逐张直出。** 只上传当前道具的 RGBA 副本，等比采样至短边 2048；提示词填写游戏原宽高。通过已配置的网关请求 2048×2048 透明 PNG；实际返回尺寸以解码为准，最终恢复原尺寸。画风示例不上传。 代表图单路。默认模型为 `gpt-image-2.5-sunburst`，质量为 `high`；显式传入 `background=transparent`、`output_format=png`。保存实际提示词、源图及上传副本校验值、模型、参数、时间和原始返回。
4. **恢复并复核。** 高清原稿保存在 `raw/`。仅等比缩放并对齐原画布，验收 `恢复图/` 的实际宽高、透明边缘和摆放。恢复稿任一边差 1 像素即退回。在请求记录中查上传尺寸、请求尺寸和实际返回尺寸，在恢复核验中查最终导出尺寸；锁定原图 Alpha 前先算主体重叠率，低于 0.85 待复核。轮廓未通过时单列原因，代表图未放行不扩批。服务不能返回真透明 PNG 时暂停。

5. **批次放行。** 每组是一个检查节点。首组全检，通过率至少 90%；后续组按编号等距抽 20 张，至少 19 张通过；不足 20 张全检，门槛 90%。所有额外异常逐张处理。用 `checkpoint <批次> --group N` 列出样本；人工确认无共性问题后追加 `--no-common-issue`，只放行剩余技术合格且未退回的稿件。
6. **续跑。** 代表图单路；同组变体按 `PROP_IMAGE_CONCURRENCY` 提交，最多 8 路。发生重试后，本次调用后续任务降为单路。429 或明确声明未开始处理的 408/500/502/503/504 最多重试两次，等待 5、15 秒或更长的服务端要求。超时、结果不明、已留下请求记录的文件暂停核查，不自动重发。
