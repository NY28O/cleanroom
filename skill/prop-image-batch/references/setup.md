# 第一次配置道具图修图

能预检原图，只需要 Python 和 Pillow。要实际出图，还需要一个支持图像编辑的服务。配置检查不上传图片。

**先确定用哪个服务。** 团队统一提供服务时，向管理员要三项：API 基础地址（含服务要求的版本前缀）、你个人的访问密钥、允许使用的图像编辑模型标识。使用自己的服务时，到该服务的开发者控制台领取密钥，从它的图像编辑文档确认地址、模型和权限。不要把网页登录地址当作基础地址。没有服务也可以先用预检功能。

| 配置名称 | 在本机填写什么 |
| --- | --- |
| `OPENAI_BASE_URL` | 服务提供的 HTTPS 基础地址，不追加 `/images/edits`。团队提供的本机代理也可用 HTTP 回环地址。 |
| `OPENAI_API_KEY` | 该服务的个人访问密钥，仅在本机输入。 |
| `PROP_IMAGE_MODEL` | 服务方给出的图像编辑模型标识。可省略，但内置默认模型不一定在你的服务可用。 |

**Windows：** 在开始菜单搜索“编辑账户的环境变量”。在“用户变量”中新建或编辑上表的变量，逐项填写，确定保存。完全退出并重新打开运行 Skill 的应用和终端，再让 AI 检查。无需管理员权限。不要发送包含密钥的截图。

**macOS / Linux：** 要临时试用，可在自己的终端运行 `bash`，再逐行执行以下命令。按提示在本机输入；密钥不会显示，也不会写入命令历史。请在**同一个终端**运行 Skill，或从该终端启动使用它的客户端。退出这个 shell 后设置即失效；已打开的桌面应用不会自动继承。长期使用可用团队的密钥管理工具向启动进程注入同名变量。

```bash
read -r -p 'API 基础地址：' OPENAI_BASE_URL
read -r -s -p '个人访问密钥（输入后按回车）：' OPENAI_API_KEY; printf '\n'
read -r -p '图像编辑模型：' PROP_IMAGE_MODEL
export OPENAI_BASE_URL OPENAI_API_KEY PROP_IMAGE_MODEL
```

**缺 Python 或 Pillow：** Windows 可先试 `py -3 --version`，macOS/Linux 可试 `python3 --version`。没有 Python 3.9 或以上版本时，先用团队软件中心或 Python 官网安装，再打开新终端。用同一解释器执行 `-m pip install -r "Skill 安装目录/requirements.txt"`（换成实际路径）。如系统不允许装包，先用 `-m venv .prop-image-venv` 创建虚拟环境，再用其中的 Python 安装和运行。Windows 解释器在 `Scripts/python.exe`，macOS/Linux 在 `bin/python`。

**怎么知道配置好了？** 请 AI 重新运行 `check-install` 和 `doctor`。前者说明能否预检，后者检查本地服务配置。若仍提示缺变量，先确认是在填配置的同一账户、同一运行环境。只有用户要求真实试跑后，服务对一张代表图返回有效的透明 PNG，才报告“已验证能出图”；图片是否通过轮廓验收另计。

**真实试跑报错：** 401/403 先检查密钥是否属于该服务、是否有图像模型权限；404 检查基础地址前缀、模型名；400 检查服务是否支持图像编辑、原图目标尺寸、透明 PNG 和 base64 返回；429 检查配额或服务限流。排查时仅提供状态码、请求编号或脱敏错误，不提供密钥。超时或请求状态不明，先向服务方核对，不自动重发。
