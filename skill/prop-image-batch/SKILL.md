# 道具图批量修图

所有命令使用本文件旁的 `scripts/batch.py` 的**绝对路径**。下文用 CLI 代指该路径。无需项目仓库。工作区默认是当前目录下的“道具修图工作区”；需要指定时在子命令前添加 `--workspace "目录"`。续跑沿用同一工作区。不要把原图库或 Skill 安装目录用作输出目录。

**安装或配置请求**：如用户只给仓库 URL，从仓库的 `skill/prop-image-batch` 子目录安装。找到 Python 3.9+，运行 `python -B CLI check-install`。缺 Pillow 时在用户的本地 Python 环境（优先使用虚拟环境）用该解释器执行 `-m pip install -r "本 Skill/requirements.txt"`，再运行检查。仅配置时不建批次、不生成图片。实际出图需用户本机已有兼容服务的 OPENAI_BASE_URL、OPENAI_API_KEY，建议设置该服务支持的 PROP_IMAGE_MODEL。只报告有无配置，不读取或回显密钥，不要求把密钥发到对话里。服务须支持单图编辑、目标宽高、透明 PNG 和 base64 返回。离线配置检查不代表服务已连通。

**运行请求**：取得明确的原图库目录和起止组号。“前三组”是 1–3。只从指定目录顶层取原图，不搜索替代目录。
1. 执行 `python -B CLI preflight --start 1 --end 3 --source-dir "原图库"`（替换实际参数）。失败就停止；用户只要求预检时到此结束。
2. 新批次用相同参数执行 `init`，记下输出的绝对批次路径；续跑核对 meta.json 的范围与原图库后，继续已有批次。执行 `submit "批次"`，再执行 `restore "批次"`。只上传对应原图和正式提示词。本组代表图未被人工放行不继续提交。
3. 用批次内的复核.html 和恢复核验.json 展示原图与恢复稿。技术未过、返回不透明或请求状态不明时暂停；不改原始 Alpha，不自动重发。依照 [批量规则](assets/01_规则与提示词/批量运行规则.md) 和 [验收标准](assets/01_规则与提示词/图片编辑与验收规则.md) 按组检查。
4. 人工确认后 `accept "批次" 文件名...`；退回用 `reject "批次" 文件名... --reason "原因"`。用户明确要求入库时才 `publish "批次" 文件名...`。不覆盖同名成品。`status "批次"` 可查台账。
